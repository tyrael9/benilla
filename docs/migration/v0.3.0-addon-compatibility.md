## CI strategy

## CI strategy

Pull requests now run a fast Linux lane: Rust formatting, documentation/catalog/span checks, and the focused `benilla-ui` Gamepad Lua bridge unit tests. This avoids rebuilding the full Bevy player, all asset/format crates, and the Windows workspace for each controller iteration. Incremental compilation is enabled on this lane and Rust cache is retained between runs.

The full Linux workspace validation (workspace Clippy/tests, addon harness smoke tests, reference-table parity and player checks) and full Windows workspace tests/player link check remain available through **Actions → CI → Run workflow** (`workflow_dispatch`). Run that full matrix before considering the migration ready to merge/release. The PR fast lane is intentionally not a replacement for platform/runtime validation; in particular it does not yet validate SDL3/iOS device polling or live addon interaction.


## 1. Packaging decision

The v0.3.0 baseline ignores `/benilla-config` in `.gitignore` because it is per-user runtime state. The fork's addons therefore must not be copied into that ignored directory and then mistaken for tracked source.

For this port, portable addon source is stored in the tracked `addons/` directory:

- `addons/BenillaController/`
- `addons/BenillaMobile/`
- `addons/MinimapMover/`

At runtime, copy or install these folders into the user's `benilla-config/AddOns/` directory. The checked-in source remains independent from local saved variables and account configuration.

The joystick TGA is reused as its existing Git blob from the old fork; it is not regenerated or modified.

## 2. Compatibility findings

### 2.1 Addon loader and test seam

v0.3.0 has a real addon discovery/loader path:

- `crates/benilla-app/src/ui_script/addons.rs` discovers one directory per addon and requires a matching `<Name>.toc`.
- The loader parses the TOC with `benilla_ui::toc::Toc`.
- `Bindings.xml` is loaded separately after the addon's TOC-listed Lua/FrameXML files (it does not need to be listed in the TOC), parsed by `benilla_ui::bindings_xml`, then registered with `UiScript::register_addon_bindings`. The order matters because the XML commands may reference functions defined by the addon's Lua files.
- `crates/benilla-app/examples/addon_harness.rs` accepts an explicit AddOns root and `--probe <Name>`; it loads the addon, seats a session, drives startup, and reports load/session errors.

This gives us a repeatable compatibility check without a local WoW installation or display. It is much stronger than static grepping, although it is not a replacement for testing the UI on a running client/device.

### 2.2 BenillaController

**Reuse:** the full FrameXML presentation and action-bar logic, including eight physical buttons, the 1–8 / 9–16 / 17–24 layers, cooldown/count/range state, drag/drop, and the stance-aware slot resolver.

**Required adaptation:** the old addon called `IsGamepadConnected()`. The old core exposes the Lua function `Gamepad_IsConnected()`; the old spelling is not part of that bridge. The tracked v0.3.0 copy now feature-tests and calls `Gamepad_IsConnected()`, defaulting to disconnected when the core bridge has not yet been ported. This prevents a Lua load/session error while the native controller layer is still under implementation.

**Bridge status:** the first v0.3.0 `Gamepad_*` Lua bridge is now implemented in `benilla-ui`: it exposes the old query/configuration globals and a public `UiScript::set_gamepad_state` snapshot setter. Unit tests cover controller state reads, axis values, touch-stick settings/clamping and the platform touch-device flag. The app-side SDL3/iOS poller does not call the setter yet, so the snapshot remains disconnected and the controller bar correctly stays hidden. This is a partial bridge, not completed controller support.

**Bindings:** `Bindings.xml` declares 24 action commands and modifier commands. v0.3.0's addon loader supports addon binding XML, so it is kept as a separate manifest file. Actual command execution still requires the future native controller binding integration and addon global functions.

**Regression gate:** base slots 1–8 must use the same stance-aware resolver for both icon display and activation. Modifier slots 9–24 must remain fixed. This behavior is retained in the copied addon but not yet end-to-end validated on v0.3.0.

### 2.3 BenillaMobile

**Reuse:** the 4×3 action bar, 12-slot paging, 120-slot reach, button resizing/positioning, cooldown/count/range presentation, and slash-command configuration.

**Conditional features:** touch-stick APIs are all feature-tested. Without the future native bridge, the stick remains hidden and no attempt is made to call missing globals. With a physical controller, the addon hides the touch stick and can auto-hide the mobile bar according to its saved settings.

**Assets:** `Textures/BenillaJoystick.tga` is included at the path referenced by the Lua source.

**Remaining validation:** run the v0.3.0 addon harness for clean load/session startup; then manually verify all button and texture/model methods on the actual runtime. The harness can report missing methods and template issues; it cannot prove touch delivery, visual layout, or finger ownership.

### 2.4 MinimapMover

**Reuse:** saved position, lock/unlock/reset commands, whole-cluster movement with drag initiated on `Minimap`, and preservation of the existing drag scripts through a compatibility wrapper.

**Remaining validation:** verify `MinimapCluster`/ `Minimap` availability, script callback semantics, drag movement, saved-variable persistence and interaction with the stock minimap in the running client. The addon harness is the first check, not final proof.

## 3. Changes in this integration pass

- Added the three addon folders under tracked `addons/`.
- Reused the joystick TGA blob.
- Corrected the controller addon connection check to the old core's actual Lua bridge spelling, guarded until the new bridge exists.
- Added `scripts/check-fork-addons.py`, which probes each addon with the v0.3.0 addon harness and requires zero load errors and zero session-start errors.
- Added the smoke check to the Linux CI gates.

## 4. What this does not claim

- The SDL3/iOS GameController input adapter is not ported.
- The `Gamepad_*` Lua bridge and script-model snapshot setter are implemented and unit-tested; platform input has not been connected to the setter.
- The 24 controller commands are not wired to the new binding engine.
- Touch input, virtual cursor, movement, swimming, targeting and interaction are not implemented.
- The smoke test does not validate rendered appearance or hardware input.
- The iOS packaging script is not yet ported or validated.
